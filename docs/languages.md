# Website languages

The language selector has three modes:

- **默认 / Default** restores the original website: mostly English interfaces and Chinese posts.
- **中文** switches interface and introduction text to Chinese.
- **English** switches Chinese article text and game introductions to English.

The choice is saved locally under `amy.site-language`. The personal website, Studio, and the game introduction share it when hosted on the same `amy22707.github.io` origin. Previews on different ports do not share browser storage.

The globe selector is rendered directly in the shared header, including on
Publications, and enhanced by the browser runtime. The compact menu centers its
button and options on the same axis, using “默认 / Default” on wide screens and a
short label when space is limited. Without JavaScript, the native selector remains.

## What stays unchanged

- Friends' names and descriptions in Links (`translate="no"`).
- PDF/PPT attachments, images, source Markdown, code blocks, inline code, and mathematical formulas.
- Link destinations, heading IDs, downloaded filenames, and copied friend-link snippets.
- Account names and technology/product names where appropriate.

Only visible page text, titles, descriptions, and accessibility labels are translated. The original content remains the default and can always be restored using the selector. English translations begin as machine-generated drafts, with manual corrections for terminology, names, and context; they should not be treated as an independently verified technical reference.

## Files

- `public/i18n/runtime.js`: browser language switcher; no visitor text is sent to a translation service.
- `public/i18n/language.css`: language control and responsive typography.
- `public/i18n/site.json`, `pages.json`, `pages/*.json`: generated static dictionaries; commit these with the website.
- `src/i18n/overrides.json`: manually checked shared translations, keyed by the original text.
- `src/i18n/page-overrides.json`: contextual corrections for a specific HTML route. This avoids changing the meaning of short fragments everywhere.
- `.studio-workspace/i18n/`: ignored local inventory and translation cache. Do not publish these caches.
- `.studio-workspace/amy-studio/site/i18n/`: Studio's separate copy of the runtime and its own dictionaries. Commit these in the Studio repository, not only in the personal-site repository.

## Whole-sentence translations for mixed inline content

Chinese sentences containing inline code, formulas, links, or emphasis are now
translated as complete inline runs, not by concatenating independently translated
text nodes. Nested lists and block code fences are boundaries, not movable inline
content. This rollout supplies English sentence templates for the current Chinese
content; ordinary interface text continues to use the existing dictionaries.

- `public/i18n/inline-blocks.mjs` serializes inline structure and safely renders it.
- `public/i18n/blocks/` contains generated, page-specific sentence dictionaries.
- `src/i18n/block-overrides.json` contains manually reviewed **complete sentences**.
  Keys are the original sentence templates (a complete context key can also be used).
- `scripts/i18n-terms.mjs` normalizes the small, source-scoped terminology list.
  Original English titles, code identifiers, and numerical statements are not rewritten.

An atomic placeholder such as `[[A0]]` retains an existing code/formula/image node.
Paired markers `[[O1]]...[[C1]]` retain an existing link or formatting element but
allow its label to be translated in context. Markers must occur exactly once, be
balanced, retain nesting, and not erase a previously nonempty link/formatting label.
Translations are rendered with text nodes and original element references, **never
by inserting translated HTML**. Code, math markup, hrefs, IDs, and element listeners
are retained. Default mode restores the original nodes and text.

Whole-sentence entries take priority over legacy fragment entries. When reviewing a
mixed-content sentence, edit `block-overrides.json`, not just a fragment in
`overrides.json`. New content without a valid whole-sentence translation stays in its
original language with a notice, rather than displaying a misleading fragment assembly.

The initial sentence drafts were generated by a translation service and key technical
and game-instruction examples were checked manually. Structural validation is not a
claim that every new English sentence has received a full human linguistic review.

After building the original pages, collect and generate sentence dictionaries:

```powershell
node scripts/collect-i18n-blocks.mjs
# Optional, only with consent to send pending public article text to Bing Translator:
pwsh -File scripts/translate-i18n-blocks.ps1
node scripts/build-i18n-blocks.mjs
npm.cmd run build
node scripts/check-i18n-blocks.mjs
npm.cmd run test:i18n
```

Draft generation sends sentence text and markers, not the contents of protected
inline code/formulas. The local draft cache remains under ignored
`.studio-workspace/i18n/`. Commit the generated `public/i18n/blocks/` files and
Studio's corresponding dictionaries; normal site builds do not call a translator.
The browser test fixture is available through `npm.cmd run preview:i18n` at the
printed localhost URL and is not deployed as a public page.

The preservation check used for this migration snapshots the reviewed dictionaries
before generation (`node scripts/check-i18n-preservation.mjs --snapshot`) and compares
them afterward. It permits only the source-scoped terminology changes, not a return
to older machine drafts. Current reviewed dictionaries now take priority over old
worker caches when generating assets.

## Updating translations after editing content

Run from the `my-homepage` repository root with Node.js available:

```powershell
npm.cmd run build
node scripts/collect-i18n.mjs
```

The collector reads rendered HTML, skipping protected content. Add or correct translations in the two override files. Existing dictionaries remain usable even without the ignored caches; for a fresh checkout, regenerate the local inventory and obtain drafts only if new translations are needed.

The optional draft generator is **not** part of `npm run build` or deployment:

```powershell
pwsh -File scripts/translate-i18n.ps1
```

It sends pending, unprotected text to Bing Translator. Only run it when you consent to sending that text. It does not use personal credentials and does not store the public translation session token. Completed cache entries and shared manual overrides are reused. The public endpoint may be rate-limited or change; if it fails, keep the existing dictionaries and supply manual overrides rather than blocking deployment.

After reviewing any new drafts:

```powershell
node scripts/build-i18n.mjs
npm.cmd run build
node scripts/check-i18n.mjs
```

Then build Studio from its own repository:

```powershell
cd .studio-workspace/amy-studio
node scripts/build.mjs
```

Normal builds and GitHub Actions use the committed static dictionaries and never contact the translation service. Publishing requires pushing the relevant changes in **both repositories**; building locally alone does not update the online sites.

## Travel Frog availability

The introduction page is `/studio/travel-frog/` in the personal-site repository. The Studio card is configured in Studio's `site/data/studio.json`; play and download URLs now point to the published web entry and releases. Translation maintenance must retain those URLs and never change software packages or translate the game client itself.

Published dictionaries may contain source-language fallbacks, including Chinese
text with only its punctuation changed. These are pending translations, not
reviewed English; they must not mask a newly generated translation. Preserve
existing meaningful translations and manual overrides when refreshing assets.

Sentence generation follows the same rule: current manual overrides take priority,
then valid entries in the exact page/context catalog, then local draft caches.
Missing caches must not erase committed translations. `npm.cmd run test:i18n`
checks this precedence and the four reviewed contexts that previously missed their
overrides, in addition to placeholder and fallback behavior.
